# Waymaker repository audit and improvement plan

Date: 2026-11-04. Baseline: `main` at `1fad316` (v0.6.0), clean worktree.

This audit covers correctness, interactive UX, performance, code health, build/CI/release, configuration, documentation and repository hygiene. Each finding is marked as **measured** (reproduced or counted during this audit) or **observed** (read from the source or config, not exercised).

---

## 1. Summary

The engineering foundation is solid. Clippy runs clean with `-D warnings` across the feature matrix. GitHub Actions are pinned by SHA, and the toolchain is pinned. CI also runs cargo-deny, a coverage floor, pty-driven end-to-end tests, signed release provenance and an install script that verifies checksums. Interactive frame times are well inside the 16 ms budget.

The weak spots are elsewhere:

1. **The shipped default config intercepts printable characters.** In the default picker you cannot type `*` or `?` into the query (measured).
2. **The headless filter is slower than fzf on selective queries and uses about 3× the memory** (measured).
3. **The repository carries leftover files and stale metadata from the upstream fork.** This includes a tracked 10.6 MB binary, scratch `.rs`/`.py` files, personal session files, dead release tooling configs and about 50 stale `matchmaker` references.
4. **The docs overstate or misdescribe parts of the product.** There is a crates.io badge for an unpublished crate, 5 broken relative links, and an architecture doc that is thin and anchored to line numbers.
5. **Some public actions do nothing.** `HistoryUp`/`HistoryDown` are empty stubs, and `CycleSort` is compiled out of release builds.

## 2. Correctness and UX defects

### 2.1 P0: `*` and `?` cannot be typed in the default picker (measured)

`waymaker-cli/assets/config.toml` binds bare printable characters at the top level, where they apply in filter (query) focus:

```toml
"*" = "@bookmark"
"?" = "Help"
"shift-?" = "Help"
```

Reproduction (tmux, `--config waymaker-cli/assets/config.toml`, isolated `HOME`):

- Type `a*`. The query stays `a`, and the status line shows `󱀻 Bookmarked: a*b`. This is a side effect: the item is written to the persistent bookmark store.
- Type `w?`. The query stays `w`, and the Help panel opens.

The same binds exist in `win.config.toml`, `dev.toml` and `reference.config.toml`, and `*` is also bound in `presets/jump.toml`. Glob-style queries (`*.rs`), regex-ish queries and literal `?` are impossible in the default picker. In addition, an accidental keystroke **mutates persistent state**.

**Fix:** move printable-character binds into the nav-mode bind table (`[ui.nav.binds]`, gated behind `Esc`/picker focus). Keep chords (`ctrl-*`) in `[binds]`. Add a pty test that types `*?` and asserts the query reads `*?`. Also add a config-load warning when a bare printable key is bound in filter focus.

> Side note: while reproducing this, the audit wrote a stray `a*b` bookmark into the real store. It was removed with `wm unbookmark`.

### 2.2 P1: `Esc` exits with status 1, the same as "no match" (measured)

`"esc" = "Quit(1)"`, and since `653c311` the code for "nothing matched" is also 1. A script cannot tell "the user cancelled" from "the input had no matches". fzf uses 130 for cancel, and `binds.md` already documents `Quit`'s default as 130. **Fix:** change the shipped binding to `"esc" = "Quit"` (130) and note the change in `CHANGELOG.md` as a behaviour change. This decision was already pending with you, recorded on 2026-10-24.

### 2.3 P1: public actions that silently do nothing (observed)

- `MMAction::HistoryUp` / `HistoryDown` (`waymaker-cli/src/action.rs:272-277`) are `// todo` bodies. They are documented as "(TODO)" in doc comments but can be bound like any other action.
- `MMAction::CycleSort` only works under `feature = "experimental"`. Release binaries are built with default features (see 5.3), so binding it in a release build does nothing.

**Fix:** either implement query history (persisted per preset, about 200 lines) or reject these actions at config-parse time with a clear error. A bind that silently does nothing is the worst outcome.

### 2.4 P2: keybinding ergonomics in shipped defaults (observed)

- 30 `alt-*` binds across `config.toml`, `jump.toml`, `downloads.toml` and `ps.toml`. Several of these have no home-row equivalent: `alt-1`/`alt-0` jump to the ends, `alt-=`/`alt-hyphen` resize the preview, and `alt-p`/`alt-y` print and copy. Alt chords are fzf-conventional, but on a MacBook they force thumb adduction, and some terminals send Option as a composed character unless configured otherwise.
- `F1`–`F12` are reserved for `@help`…`@save`. That is fine as aliases, but none of them should be the only path to an action.
- `ctrl-u` is `Cancel` (clear query) in the global config but "ancestor jump" in `jump.toml`. Reusing one chord for two meanings across presets weakens muscle memory. Consider `ctrl-u` = clear everywhere (readline convention) and moving ancestor jump to nav-mode `U`.

See the cost matrix in section 9.

## 3. Performance

### 3.1 Measurements

Environment: Linux 7.1.6 (Arch, aarch64), installed release binary `wm 0.6.0` (18.5 MB). Corpus: 2,000,000 synthetic path-like lines (113 MB). Each figure is the median of 3 runs, `-f` headless mode, output to a pipe.

| Query | Matches | wm (current) | wm (v0.6.0 idle) | fzf | sk |
| :--- | ---: | ---: | ---: | ---: | ---: |
| `mod97file12` (narrow) | 27,305 | **199 ms** | 264 ms | 202 ms | 613 ms |
| `src/module_5` (broad) | 1,559,075 | **424 ms** | 625 ms | 1,128 ms | 2,521 ms |
| `xyzzy` (no match) | 0 | **189 ms** | 249 ms | **171 ms** | 241 ms |
| Startup, empty stdin | — | 3.3 ms | 3.3 ms | 1.9 ms | 4.7 ms |
| Peak RSS, narrow query | — | **357 MiB** | 770 MiB | 244 MiB | 296 MiB |
| Peak RSS, broad query | — | **401 MiB** | — | 534 MiB | — |
| Binary size | — | 18.5 MB | 18.5 MB | 5.2 MB | 7.0 MB |

*(Note: initial measurements of 921 ms / 2,113 ms / 468 ms were taken while background build/test processes were active; the table above reflects an idle machine.)*

Interactive streaming (`--benchmark-input mod97`, 300k items, 124k matched): p50 0.167 ms, p90 2.7 ms, p99/max 7.6 ms per frame across 13 frames. That passes the 16.67 ms budget comfortably.

All three tools returned the same top result for every query, so ranking quality is at parity on this corpus.

### 3.2 Analysis

- **Fixed per-item cost dominates when few items match.** The no-match query costs wm 468 ms against fzf's 160 ms. Since no output is produced, this is pure ingest + match cost. Likely contributors (to be confirmed by profiling, not yet measured):
  - per-line `String` allocation in `map_reader_batched`, plus a separate UTF-32 haystack per column inside nucleo;
  - column splitting and preprocessing (`ansi`, `trim`) applied even when there is one column and both are off;
  - in `start_filter` (`waymaker-cli/src/start.rs:2512`), `while !handle.is_finished() { tick(10) }` spins a tokio worker thread on `tick(10)` while ingest runs on the same runtime.
- **Memory is about 3× fzf's.** At 2M items, 769 MiB is about 385 bytes per line for lines averaging 57 bytes. Storing both an owned `String` and a `Utf32String` per item, plus per-item column metadata, accounts for most of it. fzf stores bytes once, plus a chunk index.
- **Broad queries are where wm wins.** Parallel matching plus `std::mem::forget(mm)` at exit (skipping the free of 1.5M items) beats fzf by 30%.
- **The binary is 3.5× fzf's size.** Mermaid rendering (`mermaid-rs-renderer` + `mermaid-text` + 2,294 lines of `utils/mermaid.rs`), `resvg`/`usvg`/`tiny-skia`, `image` and `ratatui-image` are always compiled in. 350 unique crates are in the normal dependency graph.
- **Blocking sleeps in startup paths.** `cache.rs:187` and `frecency.rs:380` retry `redb` opens with `std::thread::sleep(25ms)` up to 10 times (250 ms worst case), and `watch.rs:52` sleeps up to 45 ms re-reading a file. If any of these run on a tokio worker, they stall the runtime.

Main issues:

1. **God files.** `start.rs` mixes config destructuring, the walker, reload logic, the headless filter and the benchmark harness. `start_filter` and `start_benchmark_input` duplicate the same 30-line `Config { .. }` destructure. `cli/action.rs` holds both the `MMAction` enum and its 2,000-line handler.
2. **The workspace dependency pins are inconsistent with the actual versions.** The workspace declares `waymaker-lib = { version = "0.3.*" }` and relies on `[patch.crates-io]` to point at the path. That works only because nothing is published. Prefer `{ path = "waymaker-lib", version = "0.3" }` directly and drop the self-patches.
3. **Matcher fork dependency.** `nucleo` comes from `Squirreljetpack/nucleo@mm` (an upstream author's branch, pinned only by the lockfile). If that branch is force-pushed or deleted, fresh clones without the lockfile break. Fork it under `felipecm-br`, or vendor it.
4. **Two mermaid stacks.** Both `mermaid-text` and `mermaid-rs-renderer` are dependencies, alongside a 2.3k-line in-house module. Pick one.
5. **Test isolation.** Debug builds read and rewrite `<config_dir>/waymaker/dev.toml`. This is good for development, but it is a trap for anyone validating behaviour with a debug binary. Gate it behind an env var (`WM_DEV=1`) instead of `cfg(debug_assertions)`.

## 5. Build, CI and release

Already in good shape: SHA-pinned actions, pinned toolchain `1.99.1`, clippy across 3 feature sets plus Windows, cargo-deny, coverage floor, macOS split into its own workflow, Dependabot grouped weekly, signed build provenance, `install.sh` checksum verification.

Gaps:

1. **No `cargo fmt --check` in CI.** The tree is already formatted, so the earlier reason to defer (avoiding merge conflicts with feature branches) is gone. Add the check now.
2. **No Windows tests.** Windows ships a release binary but only gets clippy in CI. Start with `cargo test -p waymaker-partial -p waymaker-partial-macros` (platform-independent), then expand.
3. **Release builds are not `--locked` and use default features.** `taiki-e/upload-rust-binary-action` defaults to an unlocked build. Pass `locked: true` so the released binary matches CI's lockfile. `[package.metadata.dist]` declares `features = ["experimental"]`, but `release.yml` builds without it. Decide which is intended.
4. **No performance regression gate.** `benches/matcher.rs` (Criterion) and `--benchmark-input` exist but never run in CI. Add a non-blocking job that runs the filter benchmark on a fixed corpus and posts the numbers to the step summary.
5. **Dead release tooling.** `dist-workspace.toml` (cargo-dist, which pushes to the `Squirreljetpack/homebrew-tap` and `@squirreljetpack` npm scope) and `release-plz.toml` are not used by any workflow, and AGENTS.md describes a different, manual release process. Delete both, or adopt one deliberately.
6. **`.gitignore` has `*.txt`.** That silently ignores any future `SHA256SUMS.txt`, test fixture or `LICENSE.txt`. It also references `matchmaker-cli/assets/presets/todo`. Replace it with specific patterns.

## 6. Configuration

- `config.toml` is meant to equal `Config::default()`. Good: it is the single source of truth for defaults, and the pty tests run against it. Keep the reference config generated from (or tested against) it so `reference.config.toml` (36 KB) cannot drift.
- ✅ (`win.config.toml` only) Now generated by `build.rs` from `config.toml` plus `assets/win.overrides.toml` (6 shell-specific binds); the old copy had drifted in 73 lines. `win.dev.toml` (developer-only, behind `WM_DEV=1`) and `win.rg.toml` (a genuinely different PowerShell preset) stay separate. Original note: the Windows twins (`win.config.toml`, `win.dev.toml`, `win.rg.toml`) duplicate about 90% of their Unix counterparts. Use the partial-merge model already in the codebase: base config plus a small `[target.windows]` override layer. This also fixes the `*`/`?` bug in one place instead of three.
- The default preview command is a 600-character inline shell one-liner using `[[ … ]]`, which is a bashism. It works only if the configured shell is bash or zsh. Move it to a shipped script (`wm preview-file {1}` as a built-in subcommand, since `wm tree` already exists) so it is testable, portable and Windows-safe.
- `ResultsConfig::default()` sets `current_style.bg = Color::Black` (`waymaker-lib/src/config.rs:1765`). On light themes and transparent terminals, the cursor row becomes an opaque black bar, and every preset has to override it. Change the library default to `bg = Reset` plus `BOLD`, plus a nav-bar indicator. Presets then inherit a clean selection row instead of each redeclaring it.

## 9. TUI ergonomics review (default config)

### 9.1 KLM-GOMS, common tasks (estimates)

Operators: K = 0.12 s keystroke (home row), 0.28 s for reach keys (arrows, F-keys, Alt on a MacBook); H = 0.4 s homing; M = 1.2 s mental preparation.

| Task | Today | Proposed | Saving |
| :--- | :--- | :--- | ---: |
| Search for `*.rs` | impossible: `*` bookmarks | type `*.rs` | task becomes possible |
| Jump to last item | `alt-0` (0.28 s + thumb adduction) | `ctrl-g`, or nav-mode `G` (0.12 s) | about 0.16 s per use, no ulnar strain |
| Grow the preview | `alt-=` (0.28 s) | `ctrl-]` / nav-mode `+` (0.12 s) | about 0.16 s |
| Cancel from a script and branch on the result | ambiguous exit 1, extra `M` to remember | exit 130 | removes a class of script bugs |
| Clear the query | `ctrl-u` (but means ancestor jump in `jump`) | `ctrl-u` everywhere | removes 1 M per preset switch |

### 9.2 Home row and escape cascade

- Movement (`ctrl-j`/`ctrl-k`) and accept (`enter`) are home-row in both focuses. Good.
- The `Esc` cascade should unwind state before quitting: dismiss the overlay or help panel, then clear a non-empty query, then quit (130). Today the first `Esc` quits even with text in the query. With a CapsLock tap as Esc, accidentally quitting is cheap to do and expensive to redo (the walker re-scan).
- Proposed: `"esc" = ["@unwind"]`, where `@unwind` is a built-in action that does the first applicable step of that cascade.

### 9.3 Visual defaults

- The selection row uses an opaque `bg = Black` (6.4). Replace it with `bg = Reset` + `BOLD` + a cyan `│` nav bar at x = 1.
- The footer is empty by default. A 5-item hint bar (`enter accept │ tab mark │ ctrl-p preview │ ctrl-/ layout │ ? help`, with keys in cyan bold, actions in dark grey and no brackets) teaches the binds without opening help. Once `?` moves to nav mode, the hint should read `esc ? help`.
- Preview layouts cycle right 40% → top 55% → right 75%. A right-hand split at 60/40 or 75/25 suits code and markdown best. The top-55% layout is worth keeping for wide-and-short terminals only. Consider choosing it automatically when the terminal is less than 100 columns wide.
